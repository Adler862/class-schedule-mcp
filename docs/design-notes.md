# 设计说明

记录这个服务几次关键迭代的取舍，方便后来者（也包括我自己）理解"为什么是这样"。

## 1. 为什么图片由服务端直推，而不是让智能体转发

最初的链路是：模型生成图片 → 交给智能体 → 智能体再发到微信。
实测转发不稳定（图片丢失、重复发送），而且模型有时会"加戏"——先描述一遍图片再发。

改成：**MCP 服务自己把图片推到微信通道，模型只回一句短文案**。
为此把"上传 → 加密 → 发送"三步固定成服务端函数，并让工具返回值变成给模型的行为指令
（例如"图片已作为完整回复，不要再补充说明"）。

## 2. 为什么新闻从"关键词加权"改成"板块配额制"

第一版给每条新闻打关键词分，按分数排序。结果：科技类内容天然关键词多（AI、大模型、
芯片、开源…），实测一篇早报里科技类占到 **77%**，其他板块几乎看不到。

第二版改成**板块配额**：

- 兴趣板块（时政/国际 3 条、科学/健康 2 条、校园/教育 1 条、本地/生活 1 条）优先占位；
- 全网热搜兜底 3 条；
- 科技类（AI/大模型 + 科技/大厂）**合计硬上限 3 条**，且排在最后。

同时加了 `quiet_sources`：某些来源（例如社会新闻量大的源）不参与热搜兜底，
避免它们把热搜位刷满。改造后科技类占比约四分之一，且顺序稳定。

## 3. 为什么加"来源白名单"

按关键词分类时，同一条新闻可能同时命中多个板块（例如"高校 AI 专业"既像教育又像科技）。
早期版本会出现"这条应该在校园板块，却被科技板块抓走"的错位。
现在的判定顺序是：屏蔽词 → 科技优先判词 → 兴趣板块 → 全网热搜兜底，
并对每个板块限定来源白名单，防止串板块。

## 4. 多源并发与降级

9 个数据源用线程池并发抓取，单源超时或失败只影响它自己；输出末尾会注明
"今日 N 个源暂时不可用"，这样"新闻变少"时能一眼看出是限流还是代码问题。
（60s 聚合整站限流时会返回 Cloudflare 1027，此时澎湃 + 百度四榜仍可用。）

## 5. 课表引擎的几个细节

- 周次计算支持单双周（`weekType`）与按周次列表精确控制（`weeks`）；
- 节假日/调休通过第三方接口判断，用于"今天是否上课"的提示；
- 作息时间（大节划分、课间）写在 `today_schedule.py` 顶部，换学校改这里；
- 渲染时无课的晚间大节会自动裁剪，避免图片留大片空白。

## 6. 踩过的坑

- **MCP 连不上**：表现是客户端显示连接失败，直接运行服务脚本报
  `Could not find platform independent libraries <prefix>`，甚至 0xC0000005 崩溃。
  根因是所用的 Python 解释器底座被裁剪（标准库缺失），换一个完整的解释器即可。
  排查顺序建议：先 `python -c "import sys; print(sys.prefix)"` 看解释器是否完整，
  再跑 `tests/test_mcp_handshake.py` 确认协议层是否正常。
- **改了代码不生效**：多数 MCP 客户端会缓存服务进程，改完要在客户端里把服务开关关一下再开。
- **Excel 编码**：教务系统导出的 `.xls` 用 GBK 编码，需要 `xlrd` 的 `encoding_override='gbk'`；
  有些文件扩展名是 `.xlsx` 但内容仍是旧格式，所以要"先试 xlrd，失败再试 openpyxl"。
